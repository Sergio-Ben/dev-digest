## What Works

- **2026-08-27** — For pixel-perfect design-fidelity work, `pip3 install --user Pillow` + `im.getpixel((x,y))` on the provided screenshot beats eyeballing: sampled RGB values reverse-engineer exact theme tokens by testing "is this a solid colour or an alpha-blended `-bg` token composited over the surrounding surface?" — e.g. `rgb(48,34,33)` at a legend swatch matches `var(--crit-bg)` (`rgba(239,68,68,0.12)`) composited over `--bg-elevated` (#1c1c1c) to within a few units, not the solid `--crit` (#ef4444) the existing code used. Also caught that a "code diff block" background (`rgb(12,12,12)`) was `--bg-primary`, not the `--bg-elevated` the component had hardcoded, and that a highlighted diff line's background only spans the TEXT width (`display:'inline-block'`), not the full container width. Evidence: `client/src/app/eval/compare/_components/EvalCompareModal/styles.ts` (`legendSwatch`, `diffBlock`, `diffLine`).
- **2026-08-27** — When a design screenshot omits a heading that an existing i18n key / test still expects in the DOM (here: no visible "Metric deltas" heading above the compare-modal's delta cards, contradicting `deltasHeading` and an a11y test asserting it renders), keep the `t()` call but wrap it in a visually-hidden (`position:absolute; width:1px; height:1px; clip:rect(0,0,0,0)`) style instead of deleting it — matches the screenshot pixel-for-pixel while keeping screen-reader structure and every existing `getByText` assertion green. Evidence: `client/src/app/eval/compare/_components/EvalCompareModal/styles.ts` (`srOnly`), `EvalCompareModal.tsx:130`.
- **2026-08-07** — To make a shared component (e.g. `FileCard`) support an OPTIONAL controlled `open` prop without breaking existing uncontrolled callers, check `openProp !== undefined` (not truthiness — a parent legitimately passes `open={false}`) to pick controlled vs. the original `useState`. The original uncontrolled call site (`DiffViewer`) needed zero changes. Evidence: `client/src/components/diff-viewer/FileCard/FileCard.tsx:62-67`.
- **2026-06-14** — `formatCost` (`src/lib/cost.ts`) distinguishes MISSING data (`null`/`undefined` → "—") from a genuine zero (`0` → "$0.00"), widens precision for sub-cent values (~2 sig figs), and trims trailing zeros to a 2dp floor ("$0.06" not "$0.060", "$0.0013" not "$0.00"). Reuse it for any per-run money display.

## What Doesn't Work

- **2026-08-10** — A card in the OverviewTab two-column grid must have a DEFINITE height (`h-[400px]`), not `flex-1 min-h-…`. The grid is `alignItems: "stretch"`, so the row's height is derived from its items' content: with `flex-1` the blast tree's own 100 symbol rows feed back into the row height and the card grows to fit them all instead of scrolling — `overflow-y-auto` + `min-h-0` on the inner list can't save it, because nothing ever caps the outer box. Symptom is a card that looks right on 5 symbols and runs off the page on 100. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastRadiusCard.tsx` (`CardShell`), `.../OverviewTab/OverviewTab.tsx:39-46`.
- **2026-08-10** — Raw Tailwind hues for tinted chips (`bg-indigo-400/15 text-indigo-300`, `bg-amber-500/15 text-amber-400`) are dark-mode-only: the palette is fixed, but `[data-theme="light"]` flips the surface under it, so the pill text turns unreadable pastel-on-white. There is no `dark:` variant configured — theming is `[data-theme]` on `<html>`, so `dark:` would silently follow the OS instead. Use the theme-aware pairs `--accent-bg`/`--accent-text` and `--warn-bg`/`--warn` (`vendor/ui/styles.css:10-67`), which are defined per theme. Only caught by actually loading the page in light mode. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/SymbolList.tsx` (endpoint/cron pills).
- **2026-08-08** — `client`'s `tsc --noEmit` is NOT clean on main (16 pre-existing errors as of this date, in skills/conventions/PRRow), so a genuine new error reads as background noise. That's how `page.tsx` shipped passing `prNumber`/`focusFindingId`/`onFocusFinding` to a `FindingsTab` that declared none of them — the whole `?finding=` deep link was dead props, silently ignored at runtime, with the two TS2322/TS7006 errors sitting unread in the list. Diff the error list against a stashed baseline (`git stash && tsc … > base.txt`) instead of reading it absolutely. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/page.tsx:154`, `.../FindingsTab/FindingsTab.tsx`.
- **2026-08-07** — The two vendored `@devdigest/shared` copies must differ in RELATIVE-IMPORT EXTENSION STYLE — which corrects `server/INSIGHTS.md`'s claim that "the only diffs between copies are comments". The server copy is ESM under tsx and needs `./knowledge.js`; the client is bundled by webpack, which has no `extensionAlias` configured and cannot resolve a `.js` specifier to a `.ts` file. Copying the server file over verbatim (as the lesson-2 merge did to `platform.ts`) breaks the whole client build with `Module not found: Can't resolve './knowledge.js'` — and NOTHING catches it: `tsc --noEmit` passes (TS resolves `.js`→`.ts` by design) and every vitest suite passes (vite resolves it too). Only `next dev`/`next build` fails. When syncing a contract into `client/src/vendor/shared/`, strip the `.js` extensions and actually load a page. Evidence: `client/src/vendor/shared/contracts/platform.ts:1-6`.
- **2026-07-28** — Don't reset `FindingsPanel`'s `focusIdx` with `useEffect(() => setFocusIdx(0), [shown])`: `shown` is a `useMemo` over `findings`, and `findings` gets a fresh array identity on every accept/dismiss refetch, so the effect yanks keyboard focus back to the top mid-triage. Clamp at render instead — `const focus = shown.length ? Math.min(focusIdx, shown.length - 1) : 0`. The unclamped `focusIdx` was a live bug: any filter that shrinks the list left focus invisibly past the end. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/FindingsPanel.tsx:31-52`.
- **2026-07-28** — `ReviewRunAccordion`'s `defaultOpen` is only the initial `useState` value, so a prop change never reopens it; with a stable `key={review.id}` React reuses the instance. Filtering the run list therefore leaves collapsed accordions unless an explicit effect opens them. Re-keying by `id + filter` "fixes" it but also wipes each panel's `hideLow`, every open/closed choice, and re-fires the `targetRunId` scroll effect. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/ReviewRunAccordion/ReviewRunAccordion.tsx:47-62`.

- **2026-07-28** — An absolutely-positioned popover inside the PR list gets clipped: `s.tableCard` sets `overflow: hidden` for its rounded corners, so the card is cut at the row boundary (same trap on the timeline rows). Fix is a portal to `<body>` + `position: fixed` with coordinates from the trigger's `getBoundingClientRect()` — plus scroll (capture-phase) and resize listeners, because a fixed card does not follow the page. Reuse `useHoverCard()` rather than re-deriving this. Evidence: `client/src/app/repos/[repoId]/pulls/styles.ts:95-96`, `client/src/components/FindingsHoverCard/useHoverCard.ts`.
- **2026-07-28** — A hover card separated from its trigger by a gap needs a close DELAY (~140ms, cancelled on re-enter) and the same `onMouseEnter`/`onMouseLeave` handlers spread on BOTH trigger and card. Closing straight on `mouseleave` makes the card unreachable — it shuts while the pointer crosses the gap, so a scrollable card can never be scrolled. Evidence: `client/src/components/FindingsHoverCard/useHoverCard.ts` (`CLOSE_DELAY_MS`, `hoverProps`).

## Tool & Library Notes

- **2026-08-27** — `@devdigest/ui`'s `Modal` (`vendor/ui/kit/Modal.tsx`) is the shared modal primitive (used by `CreateAgentModal`, `PromptModalBody`) but is a THIN wrapper: `role="dialog" aria-modal="true"` with no `aria-labelledby` (the title is just visible text, not programmatically linked), no Escape-key handling, and no Tab focus-trap — callers must add Escape themselves (a `window`-level `keydown` listener calling `onClose`) if they need it; a true focus trap isn't addable from the caller side without either forwarding a ref/`onKeyDown` from `Modal` itself or duplicating the primitive. Also: its header always renders an icon-only `IconBtn` with a HARDCODED `aria-label="Close"` when `onClose` is passed — any footer button whose visible text is also "Close" collides by accessible name, so `getByRole("button", {name: "Close"})` in a test returns 2 elements; disambiguate with `getAllByRole(...)` and DOM order (header X renders first), or give the footer button distinct i18n copy. Evidence: `client/src/vendor/ui/kit/Modal.tsx`, `client/src/app/eval/compare/_components/EvalCompareModal/EvalCompareModal.test.tsx`.
- **2026-08-27** — Correcting the previous entry's "a true focus trap isn't addable from the caller side": it IS addable, because `Modal` renders its dialog directly in the React/DOM tree (no `createPortal`) — wrapping the `<Modal>` call in a plain `<div ref={wrapRef} onKeyDown={...}>` lets a caller query `wrapRef.current.querySelector('[role="dialog"]')` to inject `aria-label`, focus the first focusable element on mount, and cycle Tab/Shift+Tab at the two ends, all without touching the shared primitive. Caveat found only by reasoning about jsdom, not a failing test: the Tab-cycle step filters candidates by `el.offsetParent !== null` to skip hidden elements, but jsdom has no layout engine and `offsetParent` is always `null` there — so that filter silently empties the focusable list and no-ops the wrap-around under RTL/vitest. The behavior is real in an actual browser; it is just untestable via this filter in jsdom, so don't write an RTL test asserting Tab-wraps-around without first replacing/dropping that filter (e.g. swap to checking `getClientRects().length > 0`, still false in jsdom, or just skip the visibility filter in tests). Evidence: `client/src/app/eval/cases/_components/EvalCaseEditor/EvalCaseEditorModal.tsx` (`useModalA11y`).
- **2026-07-28** — There are TWO `Severity` types and they differ: `@devdigest/shared` (`vendor/shared/contracts/findings.ts:11`) is the 3-value wire enum `CRITICAL|WARNING|SUGGESTION`; `@devdigest/ui` (`vendor/ui/primitives/tokens.ts:3`) adds a UI-only `INFO`. The UI one is a superset, so indexing `SEV[sev]` with a shared `Severity` needs no cast — but typing state or a `Record<Severity, …>` with the UI type silently admits `INFO`. Import from `@devdigest/shared` for anything data-shaped. `SEV` itself (icon + colour per severity) is exported from `@devdigest/ui`; three drifting private copies already exist (`FindingCard/constants.ts`, `RunTraceDrawer/.../FindingsSection.tsx` — the latter wrongly uses `var(--accent)` for SUGGESTION) — don't add a fourth.

- **2026-07-28** — React portals propagate events along the REACT tree, not the DOM tree: a card portalled to `<body>` from inside a clickable table row still bubbles clicks to that row's `onClick` and navigates away. Keep the `onClick={(e) => e.stopPropagation()}` on the card. Evidence: `client/src/components/FindingsHoverCard/FindingsHoverCard.tsx`.
- **2026-08-27** — `@testing-library/user-event` is NOT a `client` devDependency (only `@testing-library/react` + `@testing-library/jest-dom` are) — `import userEvent from "@testing-library/user-event"` fails vitest's import-analysis at collection time (`Failed to resolve import`), killing the whole test file with 0 tests run, not a single failing assertion. Every test in this package uses `fireEvent` from `@testing-library/react` instead; for "is this keyboard-operable" assertions, query a real `<button>` via `getByRole("button", {name})` (native buttons are keyboard-operable by browser default) rather than simulating a keypress. Evidence: `client/src/app/agents/[id]/_components/AgentEditor/EvalsTab/EvalsTab.test.tsx`, also independently hit and worked around in `client/src/app/eval/compare/_components/EvalCompare/EvalCompare.test.tsx:12` and `.../PrBriefCard/PrBriefCard.test.tsx:20`.
- **2026-08-27** — `@devdigest/ui`'s `MetricCard` (`vendor/ui/charts/MetricCard.tsx`) renders its value as `<span className="tnum">{value}{suffix && <span>{suffix}</span>}</span>` — the suffix (e.g. `%`) is a NESTED span, not a sibling text node, so RTL's default `getByText("82%")` never matches: the built-in text matcher only looks at an element's direct text-node children (`value`'s own span sees only "82"; the suffix span sees only "%"), and no single node has "82%" as a direct child. `within(card).getByText("70%")` works fine elsewhere only because `AgentSummaryCard`'s own `MetricBadge` renders `formatPct(value)` as one plain string, no nested suffix span — that pattern breaks for `MetricCard`. Workaround: pass a custom matcher function and check `element.textContent` (which aggregates descendants) instead of relying on the default direct-children behavior, e.g. `screen.getByText((_, el) => el?.textContent?.trim() === "82%")`. Evidence: `client/src/vendor/ui/charts/MetricCard.tsx:48-52`, `client/src/app/eval/[agentId]/_components/EvalAgentDetailView/EvalAgentDetailView.test.tsx` (`getByFullText`).

- **2026-08-27** — `@devdigest/ui`'s `MetricCard` `delta` prop is rendered raw (`Math.abs(delta).toFixed(2)`, no unit) — the codebase has TWO conflicting conventions for what to pass it, and neither is "correct" in the abstract, only per-design: `EvalsTab/MetricsPanel.tsx` passes `delta.recall * 100` (percentage points, e.g. "4.00") for its own card row, while the approved per-agent detail screenshot (`feature-screens/Screenshot 2026-08-26 at 21.15.57.png`) shows the RAW fraction (e.g. "↑0.04") for the same `EvalDashboard.delta.recall` field. Confirmed by pixel-measuring the screenshot's delta text against the exact fixture values (`0.04`, `-0.02`, `0.01`) already checked into `EvalAgentDetailView.test.tsx`. Don't assume MetricsPanel's `*100` convention generalizes to a new MetricCard call site — check the target screenshot's actual printed digits first. Evidence: `client/src/app/eval/[agentId]/_components/EvalAgentDetailView/helpers.ts` (`deltaPoints`, now an identity passthrough), `client/src/app/agents/[id]/_components/AgentEditor/EvalsTab/MetricsPanel.tsx:71,78,85`.
- **2026-08-27** — The design's per-run RECALL/PRECISION/CITATION table cells (`feature-screens/Screenshot 2026-08-26 at 21.15.57.png`, "Recent runs" table) are a short fixed-width `ProgressBar` (from `@devdigest/ui`) + percent text, NOT plain text — verified by pixel-scanning the screenshot: bar pixel width scales linearly with the raw 0-100 value (ratio ≈1.02 px/point) against a ~102px max, and the "track" background is literally identical to the row background color (no distinct grey capsule), so `ProgressBar`'s `bg` prop must be set to `"transparent"` to match — its documented default (`var(--bg-hover)`) would render a visibly lighter capsule the design doesn't have. - **2026-08-27** — `formatCost` (`src/lib/cost.ts`) always prepends `$`, but the approved compare-modal design shows bare numbers for the COST delta card ("0.21 → 0.23 ▲0.02", no currency symbol — verified by pixel-checking the screenshot has no `$` glyph). ## Recurring Errors & Fixes

- **2026-08-27** — Any component that calls a React Query hook (`useMutation`/`useQuery`) unconditionally on every render will throw "No QueryClient set" in a test that has no `QueryClientProvider` ancestor — including EVERY existing smoke test for that component, not just new ones. `vi.mock` the hook's module (return a static `{ mutate: vi.fn(), isPending: false, ... }`) in every test file that renders the component, directly or indirectly through a parent (e.g. `FindingsPanel.test.tsx` needed the same mock as `FindingCard.test.tsx` once `FindingCard` started calling `useEvalCaseFromFinding`).
